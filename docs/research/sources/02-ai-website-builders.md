# AI-native website builders and AI inside visual editors (Nov 2026)

## 1. The tools, by category

### A. Tools that generate code, with "select and edit" added on top

- **v0 (Vercel).** Writes Next.js, shadcn and Tailwind code. Design Mode lets you click an element in the preview and use a properties panel; changes stay a preview until you click Apply, which writes them into code as a new chat version ([docs](https://v0.app/docs/design-mode)). v0's own API guide says Design Mode "uses a model to translate rendered element descriptions and requested changes into source edits. It is not a deterministic DOM patch API" ([API v2 design-mode guide](https://v0.app/docs/api/v2/guides/design-mode), updated 2026-10-23; the API is still beta).
  - At launch, Design Mode was promoted as "quick changes… without… spending any credits" ([launch post](https://community.vercel.com/t/introducing-design-mode-on-v0/13225)). Users now say that one `<h1>` change cost about $1.50 ([thread](https://community.vercel.com/t/new-design-mode-why-do-simple-edits-now-require-ai-credits/44083)), and that targeted edits restyle neighbouring elements even when told "change nothing else" ([thread](https://community.vercel.com/t/why-v0-design-mode-applies-unsolicited-changes-to-surrounding-elements-during-targeted-edits/36673)).
  - Design Systems 2.0 imports a team's components and tokens as a reusable "skill". The older registry docs warned that v0 "is specifically trained on the default implementations of the shadcn/ui components and may struggle with any customizations" ([docs](https://v0.app/docs/design-systems-legacy)).
- **Lovable.** Generates React/Vite code; new projects get TanStack Start with server-side rendering from about May 2026 (secondary: [RapidDev](https://www.rapidevelopers.com/lovable-issues/lovable-seo-guide)).
  - Visual Edits (Feb 2025) map a clicked DOM element back to the exact JSX that renders it, using stable JSX tags, a client-side syntax tree (Babel/SWC) and optimistic DOM updates ([engineering post](https://lovable.dev/blog/visual-edits)).
  - Lovable's docs disagree with each other on whether visual edits cost credits ([docs](https://docs.lovable.dev/features/visual-edit)).
  - Programmatic access: a REST API for deploy and workspace tasks, and an MCP server (research preview, 2026-05-07) with tools like `create_project`, `send_message` and `get_diff` ([API docs](https://docs.lovable.dev/integrations/lovable-api)).
  - Traction: about $500M ARR claimed by mid-2026 and a $13.3B valuation in August 2026 (secondary: [TNW](https://thenextweb.com/news/lovable-build-economy-500m-arr-vibe-coding)).
- **Bolt.new.** Visual Edits: click an element, change it in a toolbar, queue several changes, then send them to the model in one batch. Available to all users since 2026-09-03 ([blog](https://bolt.new/blog/visual-edits)). The most common complaint is opaque token use; Bolt says most tokens go to reading and syncing project files ([guide](https://bolt.new/blog/prompting-guide)).
- **Replit Agent.** Element Selector (Mar 2025) became the Element Editor and then the Visual Editor. Simple edits go straight to code at no AI cost; complex ones go to the Agent; elements made of several parts can't be text-edited directly ([docs](https://docs.replit.com/design/visual-editor)). Users ask for multi-select and visible element IDs ([forum](https://replit.discourse.group/t/would-it-be-possible-to-allow-the-editor-to-choose-more-than-one-element-on-the-screen-could-we-see-element-ids-as-well/8565)). Raised $400M at a $9B valuation in Mar 2026 (secondary: [Sacra](https://sacra.com/research/replit)).
- **Google.**
  - AI Studio Build mode has an "annotation mode": highlight any part of the UI and describe the change ([docs](https://ai.google.dev/gemini-api/docs/aistudio-build-mode)). I found no 2026 status for Firebase Studio.
  - Stitch (Mar 2026 update) added an infinite canvas, an MCP server and SDK, Figma export, and DESIGN.md: a markdown file of design tokens plus rationale that keeps agents on-brand, released as an open draft ([SiliconANGLE](https://siliconangle.com/2026/03/19/google-upgrades-stitch-ai-interface-development-tool/); DESIGN.md details secondary).
- **Same.new** clones a URL into Next.js code and is frontend-only (secondary: [review](https://atoms.dev/blog/same-new-review)). **Anything** (formerly Create): $2M ARR in its first two weeks and a $100M valuation in Sep 2025 ([TechCrunch](https://techcrunch.com/2025/09/29/vibe-coding-startup-anything-nabs-a-100m-valuation-after-hitting-2m-arr-in-its-first-two-weeks)).
- **Figma Make** added direct visual editing in May 2026 (select an element, adjust properties, an agent edits the underlying code; limited Mac beta). Figma Sites gained "code layers", components backed by React code ([TechCrunch](https://techcrunch.com/2026/06/24/figma-adds-code-layers-support-for-animations-more-ai-features-in-new-update)). Figma's forum is full of credit complaints, including "credit model penalizes users for the agent's mistakes" ([thread](https://forum.figma.com/share-your-feedback-26/credit-model-penalizes-users-for-the-agent-s-mistakes-one-day-of-work-consumed-nearly-my-full-monthly-allocation-55700)) and Make ignoring an attached library ([thread](https://forum.figma.com/report-a-problem-6/bug-figma-make-completely-ignores-attached-library-guidelines-drained-250-credits-51374)).

### B. Visual-first platforms with AI

- **Framer.**
  - History: Wireframer and Workshop (May 2025), then Framer 3.0 on 2026-06-16 with on-canvas Agents, Branching and External Agents (Claude Code, Codex, Cursor, Gemini CLI) ([Business Wire](https://www.businesswire.com/news/home/20260616909966/en/Framer-Launches-AI-Agents), [blog](https://www.framer.com/blog/framer-3/)). Server API in open beta from 2026-02-12 (secondary). Official remote MCP server around 2026-10-22 ([framer.com/mcp](https://framer.com/mcp); date secondary).
  - Internals: Framer says its project trees are "very verbose, a lot like HTML", so it "invent[ed] our own language to express the tree and its edits". For larger changes the agent "queries and updates the tree with snippets of JavaScript" ([Building Agents for Framer](https://www.framer.com/blog/building-framer-agents/)). Harness 2 runs that JavaScript as it streams, statement by statement, in a Web Worker; the tree-modification API was rewritten as individual method calls. Result: up to 33% cheaper and 20% faster ([Harness 2](https://www.framer.com/blog/harness-2/)).
  - Pricing: AI credits on every plan. A design critique says users "cannot tell how many credits a given task will use" ([Pratt IxD](https://ixd.prattsi.org/2026/09/design-critique-framers-ai-agent-mac-ios/)).
  - Churn stories: Frigade left Framer and rebuilt its site in code by talking to Claude, in 267 commits over one week ([post](https://frigade.com/blog/we-left-framer)). Babou says Claude couldn't change labels on a linked marketplace component because instances "don't expose their internals through the API" ([HN](https://hackernews-dynamic.seasondane.workers.dev/news/48297276)).
- **Webflow.**
  - AI site builder (beta Sep 2025, relaunched Nov 2025) generates a multi-page site plus a design system on Webflow's Flowkit CSS framework (secondary: Product Hunt via [Webflow updates](https://webflow.com/updates/ai-site-builder)).
  - The MCP server exposes the Data and Designer APIs. Designer tools need a companion app open in the Designer ([docs](https://developers.webflow.com/data/docs/ai-tools), [changelog 2025-09-04](https://developers.webflow.com/home/changelog/2025/9/4)). A third-party write-up describes MCP 2.0 (Jul 2026) with headless Designer tools and says "over 30% of enterprise customers use MCP, ~90% via Claude" ([Flow Ninja](https://www.flowninja.com/blog/what-is-webflow-mcp); unverified).
  - **Source by Webflow** (Conf, 2026-09-02, research preview): agents get "direct access to the code that ships… without the constraints of an abstraction layer". Visual editing writes to the same code, with role-based access, approval paths and audit trails, and it can connect to any existing codebase ([announcement](https://webflow.com/blog/introducing-source-by-webflow), [CMSWire](https://www.cmswire.com/digital-experience/webflow-launches-source-agentic-workspace-for-marketers/)). This is a strategic move by the main visual-abstraction vendor toward code as the source of truth.
- **Wix Harmony** (2026-01-21): the agent Aria plus classic drag-and-drop. Aria generates sections, adjusts colours and adds or edits elements. Harmony sites can't be migrated to or from the older Wix editors ([support](https://support.wix.com/en/article/wix-harmony-editor-working-with-aria), [press](https://www.wix.com/press-room/home/post/wix-launches-wix-harmony-the-ai-website-builder-that-merges-human-and-artificial-intelligence-rein)). The Wix MCP is hosted, uses OAuth, and offers REST plus scripted multi-call tools ([dev docs](https://dev.wix.com/docs/sdk/articles/use-the-wix-mcp/about-the-wix-mcp)).
- **Squarespace Blueprint**: a questionnaire produces a templated site, which you then edit by hand ([blog](https://www.squarespace.com/blog/blueprint-ai-website-builder)). **Durable**: about 30-second generation with per-section "regenerate" and limited layout control ([TechRadar](https://www.techradar.com/pro/software-services/durable)). **10Web**: Elementor/WordPress output, with a white-label API and reseller dashboard ([10Web](https://10web.io/website-builder-api/msps-and-agencies/)). **Dora**: 3D/animated sites, maturity disputed (secondary). **Hostinger AI Builder** (2026-08-18) merged Horizons and its site builder into two modes: an agentic mode where only static text is directly editable and everything else goes through chat, and a manual mode for moving sections ([support](https://www.hostinger.com/support/11695969-hostinger-ai-builder-agentic-mode-visual-editor-changes/)).
- **Relume**: prompt → sitemap → wireframe built from a library of 1,000+ components kept in parallel across Figma, Webflow and React, then export (secondary: [banani](https://banani.co/blog/relume-ai-features-and-alternatives)). It is the clearest "assemble from a section library" pipeline.
- **WordPress/Elementor**: the Abilities API in core (6.9) plus an official MCP Adapter ([WP dev blog](https://developer.wordpress.org/news/2026/02/from-abilities-to-ai-agents-introducing-the-wordpress-mcp-adapter/)). Elementor 4.3 added a built-in MCP that saves output as drafts, plus the "Angie" agent (secondary). **Shopify**: Sidekick generates theme blocks inside a section/block schema, on all Theme Store themes since 2025-12-10 ([changelog](https://changelog.shopify.com/posts/ai-block-generation-for-all-theme-store-themes)). One critic says the same prompt gives different blocks each time and blocks ignore the rest of the site (secondary).

### C. Hybrid visual and code editors

- **Onlook** (YC W25, Apache-2.0, about 26k GitHub stars per secondary sources): adds a build-time attribute that maps each DOM element to its source, then edits the syntax tree and writes back. Next.js and Tailwind only ([architecture docs](https://docs.onlook.com/developers/architecture)).
- **Builder.io Fusion** (Jun 2025; 1.0 on 2025-11-06): a visual canvas over your own repo and design system that outputs pull requests ([docs](https://builder.io/c/docs/projects)). Usage-based "agent credits".
- **Plasmic**: an MCP lets Claude Code, Cursor and others create pages and components inside Plasmic after reading existing tokens and components ([docs](https://docs.plasmic.app/learn/plasmic-mcp/)). Another path has the agent drive Studio through Chrome DevTools MCP and a browser-side `PLASMIC_AI_TOOLS` JavaScript API ([blog](https://www.plasmic.app/blog/using-plasmic-through-chrome-devtools-mcp)). Plasmic says a first-party AI experience is still in development.
- **Puck AI**: an MIT-licensed core editor plus a paid hosted AI layer. Two modes: "assembly", which builds pages from your registered components, and "design", which creates new component types within your guardrails. Headless `generate()` returns Puck JSON that can be rendered or handed to a human; v0.9 added custom agents. BYOK on higher plans ([overview](https://puckeditor.com/docs/ai/overview), [headless](https://puckeditor.com/docs/ai/headless-generation), [0.9](https://puckeditor.com/blog/puck-ai-09)). **Avocado Studio** is a third-party AI layer for Puck that avoids Puck Cloud ([Product Hunt](https://www.producthunt.com/products/avocado-studio)).
- **GrapesJS / Grapes Studio**: an HTML-first editor with an LLM assistant (Show HN and launch Oct 2025), an AI Chat plugin in the Studio SDK ("build AI agents that edit your projects"), and a ChatGPT/MCP app ([blog](https://grapesjs.com/blog/ai-chat-plugin-visual-editor-integration), [MCP app](https://grapesjs.com/blog/studio-mcp-chatgpt-app)).
- **Webstudio MCP**: the agent edits the real project rather than an AI copy, then opens the result in a browser and checks it with vision ([blog](https://webstudio.is/blog/webstudio-mcp-is-more-than-an-api-wrapper)).
- **Subframe**: a visual editor whose React/Tailwind code generation is deterministic, not AI-driven; it has an MCP for coding agents ([docs](https://docs.subframe.com/learn)).
- **Magic Patterns**: Design System Agent (2026-06-10) imports real tokens and components ([blog](https://www.magicpatterns.com/blog/introducing-design-system-agent)). **Tempo** ($5M seed, broadening into prompt-to-app) and **Polymet** (credit-based, shadcn export): directory sources only.

### D. Newcomers built for agents first

- **Prismic** calls itself "the agentic web platform": agents build only from slices the marketing team has approved, and every MCP edit is saved as a draft (MCP shipped 2026-06-08) ([MCP update](https://prismic.io/updates/prismic-mcp)).
- **Unlayer**, an embeddable email/page/document builder, has a hosted MCP in the official registry; designs created by an agent open in the visual builder for teammates to edit ([docs](https://docs.unlayer.com/ai/mcp)).
- **Element Node**: an AGPL "visual CMS built for AI agents", Elementor-style editor plus MCP ([AlternativeTo](https://alternativeto.net/software/element-node/about/); unverified).
- Protocols and libraries: **Vercel json-render** (early 2026, Apache-2.0) — a catalog of allowed components defined in Zod; the model outputs a JSON spec and a registry renders it ([repo](https://github.com/vercel-labs/json-render), [InfoQ](https://www.infoq.com/news/2026/03/vercel-json-render)). **Google A2UI**: agents send declarative component JSON drawn from a catalog the client already trusts ([Google blog](https://developers.googleblog.com/introducing-a2ui-an-open-project-for-agent-driven-interfaces/)).

## 2. Common interaction patterns

1. **Prompt → whole site or app** (Lovable, Bolt, v0, Durable, Blueprint, Harmony, Hostinger). This is now table stakes, and vendors are moving away from it. Framer justified its agents with "53% of website work is maintenance and edits", and Hostinger's launch line was "It's not about who can generate a homepage in 30 seconds" ([TechRadar](https://www.techradar.com/pro/its-not-about-who-can-generate-a-homepage-in-30-seconds-hostinger-launches-a-new-agentic-ai-builder-helping-businesses-do-more-with-ai)).
2. **Select an element, then tweak or prompt.** Every code-first tool shipped this between 2025 and 2026: v0, Lovable, Bolt, Replit, AI Studio, Figma Make and Hostinger. The key implementation split:
   - **Deterministic patches to the syntax tree**: Lovable, Onlook, Replit's simple edits.
   - **Model-mediated rewrites**: v0's current Design Mode, Bolt's batches.
3. **Assemble from a section library**: Relume, Puck's assembly mode, Prismic slices, Durable/Hostinger sections, Webflow Flowkit, Shopify blocks. A newer variant lets the AI create a new component within the guardrails when the library has a gap (Puck design mode, Shopify AI blocks, Figma code layers, Webflow AI code components).
4. **Sitemap → wireframe → style**: Relume, Framer Wireframer, Webflow's site builder (themes first, then a design system).
5. **Bring-your-own external agent over MCP**, the dominant 2026 trend: Framer, Webflow, Wix, Lovable, Plasmic, Prismic, Elementor, WordPress, Webstudio, Unlayer, Stitch and Subframe. The editor becomes a tool server, and Claude Code or Codex is the agent.
6. **Governed review flow**: Framer Branching, Prismic and Elementor drafts, Webflow Source approvals and audit trails, Fusion pull requests, v0 versioned Apply.

## 3. Recurring complaints and failure modes

- **Small precise edits are slow and unreliable when a model sits in the loop.** v0's spillover onto neighbouring elements (above). One developer says Framer's AI "could not produce a case study page they could ship" (Frigade). Replit can't text-edit elements made of several parts, and users want multi-select.
- **Manual edits get overwritten.** Lovable visual edits can be overwritten by a later Agent-mode prompt (secondary: [RapidDev](https://www.rapidevelopers.com/lovable-issues/preventing-lovable-from-overwriting-manual-code-edits)). In v0, manual code edits don't create versions, and one user reports edits reverting to the generated version ([Vercel thread](https://community.vercel.com/t/v0-manual-edits-disappearing-and-reverting-to-generated-version/33484)). Durable-style "regenerate section" throws away whatever you customized.
- **Costs are high and unpredictable.** Lovable "fix loops" ([lowcode.agency](https://www.lowcode.agency/blog/lovable-burning-credits-fix)), opaque Bolt tokens, Figma Make credit drains, unpredictable Framer credits, and v0 charging for trivial edits. Users resent paying for the model's own mistakes.
- **Visuals and code drift apart.** v0 edits are lost unless applied. Framer's linked component instances are opaque to its API. Webflow's MCP originally couldn't do interactions and needed the Designer open. Plasmic's agent path needs a live browser.
- **Generic design.** The purple-gradient, Inter-font "AI slop" look ([superdesign](https://superdesign.dev/blog/why-ai-design-looks-generic), [Gigazine](https://www.gigazine.net/gsc_news/en/20260423-design-slop)). Even v0 struggles with customized shadcn.
- **Lock-in and migration.** Harmony sites can't move to the other Wix editors. Frigade estimated that merging two Framer sites would take agency work costing tens of thousands of dollars. The "marketing sites don't need a CMS anymore" argument is that LLMs don't need abstractions built for humans ([HN](https://hackernews-dynamic.seasondane.workers.dev/news/48239709)).
- **SEO and performance.** Client-rendered Lovable apps were invisible to crawlers until SSR arrived in 2026; reportedly no major AI crawler runs JavaScript (secondary).
- **Valid but wrong structured output.** A Puck-based generator saw retries wrap arrays in objects and rename item keys. The fixes were validating deep inside arrays and never letting the LLM write rich-text editor state (secondary: WebDigitize write-up, mirrored at [bydfi](https://www.bydfi.com/en/crypto-news/llm-in-editor-schema-validation-lessons-25776)).
- **Agent integrations are early.** A tester found Webflow's early Designer MCP tools "didn't work that well". Framer's official MCP doesn't yet cover localization.

## 4. Structured document + component library vs raw code generation

No controlled benchmark compares the two for website editing. DesignBench, WebCoderBench and Widget2Code do not run this comparison. What exists:

**For structured documents with a catalog**
- Platform designs that bet on it: json-render's catalog-as-guardrails, A2UI's trusted catalogs (security: the payload is data, not code), Prismic's approved slices, Puck's assembly mode, and Wix's claim that Aria's edits stay within its architecture.
- One practitioner (WordPress) saw 8–12% malformed HTML when generating markup, versus under 1% with strict-schema JSON ([DEV](https://dev.to/andreata/using-llms-to-generate-structured-data-for-wordpress-not-html-23n)). This is a single author's experience, not a study.
- Deterministic tools avoid the v0-style drift: Subframe's code generation, Relume's parallel library, Lovable and Onlook's direct syntax-tree edits.

**For code**
- Aider's benchmark: models write worse code when it is wrapped in JSON (Claude 3.5 Sonnet 60.5% → 54.1%) ([aider](https://aider.chat/2024/08/14/code-in-json.html)).
- Cloudflare "Code Mode": LLMs are better at writing code that calls an API than at making tool calls directly ([blog](https://blog.cloudflare.com/code-mode/)).
- Webflow Source explicitly drops the abstraction layer for agents. The churn posts (Frigade, Babou, Figma Make users moving to Claude Code) say closed structured editors block agents.

**What this adds up to.** The most mature design keeps a structured document as the source of truth, but gives agents a compact, code-like way to read and change it:
- Framer: a custom compact tree language plus streamed JavaScript calls against a method-based tree API.
- Plasmic: the `PLASMIC_AI_TOOLS` JavaScript API.
- Webstudio: MCP plus checking the rendered result with vision.

Structure gives you validation, safe concurrent human edits, design-system enforcement and cheap deterministic edits. A code-shaped interface plays to what models are good at. Pure JSON tool calls with verbose trees are the weak point: they cost a lot of tokens and fail on shape. Pure code loses the guarantees about visual edits.

## 5. Gaps an embeddable, agent-first editor library could fill

1. **An embeddable, open, model-agnostic core.** The closest options are Puck (the AI layer is hosted and paid), GrapesJS Studio SDK (commercial), Unlayer (email-first) and json-render (rendering only, no editor). Nobody ships an open-source editor plus a headless document engine plus a built-in MCP server that you embed in your own app.
2. **Editing without a browser.** Webflow's Designer MCP needs the companion app open, Plasmic's path drives Chrome, and Swebsy needs an open tab. Agents need to read, edit, validate and render pages server-side, then hand the same document to a human in the canvas.
3. **Deterministic, typed, cheap operations.** For example: `insertSection(libraryId, at)`, `setProp(nodeId, path, value, {expect: prev})`, `applyToken`, `move`, `duplicate`. v0 says selectors are "not checked preconditions"; adding precondition checks prevents edits spilling onto neighbours. Visual tweaks should never require a model call or credits.
4. **A compact, code-shaped interface for agents.** A terse serialization of the tree, a sandboxed JavaScript/TypeScript API (code mode) alongside fine-grained MCP tools, a schema and catalog the agent can query, and streamed execution (Framer's lessons).
5. **Protecting human edits.** Record per node whether a human or an agent last changed it, offer locks or "pinned" properties, scope regeneration to one section, and merge at the operation level instead of overwriting. Add branches, drafts and approvals (Framer, Prismic, Webflow Source show demand).
6. **Large sections with fine control everywhere.** Every internal part of a prebuilt section should be addressable by the API (the Babou failure). Allow overrides without detaching, design tokens / DESIGN.md import to fight generic output, and a guarded way to create new components (Puck design mode, Figma code layers).
7. **Validation and verification as part of the library.** Deep schema checks, reference integrity, URL sanitization, layout budgets, plus render-to-screenshot so agents can check their own work (Webstudio).
8. **Clean exits.** Export to static HTML, SSR or React components, avoiding the lock-in and client-rendering SEO problems above.
9. **Predictable cost.** Since most operations involve no model call, cost can be stated per operation.

For the showcase app, the obvious demo is an external agent (Claude Code over MCP) assembling a page from large sections while a human edits a detail live, with both edit trails visible and nothing overwritten.

**Couldn't verify:** exact launch dates for Framer MCP and Webflow MCP 2.0, the Webflow adoption figures, current Lovable credit rules for visual edits, Firebase Studio's 2026 status, Tempo and Polymet's current state, and Element Node's licence and pricing. I found no independent hands-on test of how precise Wix Aria or Framer Agents are on single edits.
